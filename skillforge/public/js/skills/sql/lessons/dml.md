## Чтение — это только полдела

До сих пор мы только **читали** данные. Теперь научимся их менять. Три команды составляют **DML** (Data Manipulation Language):

- `INSERT` — добавить строки;
- `UPDATE` — изменить существующие;
- `DELETE` — удалить.

> **Безопасная песочница.** В этом курсе каждый запуск начинается с чистой копии базы — ломайте и экспериментируйте без страха. В реальной базе откатить изменения может быть невозможно, поэтому читайте раздел про осторожность внимательно.

## INSERT

```sql
INSERT INTO таблица (столбец1, столбец2, …)
VALUES (значение1, значение2, …);
```

Столбцы перечисляйте **явно**: так запрос не сломается, если в таблицу добавят новый столбец. Столбцы, которых нет в списке, получат значение по умолчанию (`NULL`, `DEFAULT` или автоинкремент для `INTEGER PRIMARY KEY`).

```sql try
INSERT INTO categories (name) VALUES ('Игры');
SELECT * FROM categories;
```

Несколько строк за раз:

```sql try
INSERT INTO categories (name) VALUES ('Игры'), ('Книги'), ('Спорт');
SELECT * FROM categories;
```

Пропущенный `NOT NULL`-столбец без значения по умолчанию — ошибка. Попробуйте добавить товар без цены:

```sql try error
INSERT INTO products (name, stock, created_at) VALUES ('Тест', 1, '2025-01-01');
```

## UPDATE

```sql
UPDATE таблица
SET столбец = выражение, …
WHERE условие;
```

```sql try
UPDATE products SET price = price * 1.1 WHERE category_id = 4;
SELECT id, name, ROUND(price, 2) AS price FROM products WHERE category_id = 4;
```

> **Самая дорогая забытая строка в SQL — `WHERE`.** `UPDATE customers SET vip = 1;` без `WHERE` сделает **всех** клиентов VIP. Привычка: перед `UPDATE`/`DELETE` напишите тот же `WHERE` в обычном `SELECT` и посмотрите, какие строки затронутся.

## DELETE

```sql
DELETE FROM таблица WHERE условие;
```

```sql try
DELETE FROM order_items WHERE order_id IN (SELECT id FROM orders WHERE status = 'cancelled');
DELETE FROM orders WHERE status = 'cancelled';
SELECT COUNT(*) AS orders_left FROM orders;
```

Обратите внимание на **порядок**: сначала удаляем позиции заказов, потом сами заказы. Иначе позиции останутся «осиротевшими» — ссылаться на заказ, которого уже нет. Многие СУБД не дадут так сделать (внешний ключ); в SQLite проверки ключей по умолчанию выключены, поэтому порядок — на вашей совести.

## Транзакции (идея)

Несколько связанных изменений нужно выполнять **целиком или никак**. Для этого служат транзакции: `BEGIN; … COMMIT;` (или `ROLLBACK;` — «отменить всё»). Пример: перевод денег — списать с одного счёта и зачислить на другой; если упало между ними, деньги не должны пропасть.

## Запомните

- `INSERT` — перечисляйте столбцы явно; `UPDATE` и `DELETE` — **всегда** проверяйте `WHERE`.
- Перед изменением напишите тот же `WHERE` в `SELECT` и посмотрите, что затронется.
- Удаляйте сначала зависимые строки (позиции), потом главные (заказы).
- Связанные изменения оборачивают в транзакцию.
