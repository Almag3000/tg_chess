## Запрос внутри запроса

**Подзапрос** — это `SELECT` в скобках, вставленный в другой запрос. Он нужен, когда ответ на вопрос состоит из двух шагов: «сначала узнай X, потом используй X».

Пример: «Какие товары дороже средней цены?» Шаг 1 — найти среднюю цену. Шаг 2 — отфильтровать по ней.

```sql try
SELECT name, price
FROM products
WHERE price > (SELECT AVG(price) FROM products)
ORDER BY price DESC;
```

## Три места, где живут подзапросы

**1. Скалярный подзапрос** — возвращает ровно одно значение (одну строку и один столбец) и работает как обычное число. Его можно ставить в `WHERE`, `SELECT`, `HAVING`:

```sql try
SELECT name, price,
       price - (SELECT AVG(price) FROM products) AS diff_from_avg
FROM products
LIMIT 5;
```

**2. Подзапрос со списком** — возвращает один столбец, используется с `IN`:

```sql try
SELECT name
FROM customers
WHERE id IN (SELECT customer_id FROM orders WHERE status = 'cancelled');
```

**3. Подзапрос в `FROM`** (производная таблица) — результат запроса используется как временная таблица. Ей обязательно нужен псевдоним:

```sql try
SELECT AVG(orders_count) AS avg_orders_per_customer
FROM (
  SELECT customer_id, COUNT(*) AS orders_count
  FROM orders
  GROUP BY customer_id
) AS t;
```

Здесь мы агрегируем **агрегат**: сначала считаем заказы по клиентам, потом берём среднее. Прямо `AVG(COUNT(*))` написать нельзя — отсюда и нужен подзапрос.

## Коррелированные подзапросы

Обычный подзапрос выполняется один раз. **Коррелированный** ссылается на столбцы внешнего запроса и логически вычисляется для каждой строки внешнего:

```sql try
SELECT p.name, p.category_id, p.price
FROM products p
WHERE p.price > (
  SELECT AVG(price) FROM products WHERE category_id = p.category_id
);
```

«Товары, дороже средней цены **в своей категории**». Для каждого товара `p` подзапрос пересчитывает среднее по `p.category_id`.

> Коррелированные подзапросы наглядны, но на больших таблицах бывают медленными. Позже вы увидите, что их часто можно заменить `JOIN` или оконной функцией.

## Ловушка NOT IN и NULL

`x NOT IN (1, 2, NULL)` **никогда** не бывает истинным: SQL не может доказать, что `x` отличается от «неизвестного». Если в подзапросе есть `NULL`, `NOT IN` вернёт пустой результат.

```sql try
SELECT 'строка вернулась' AS result WHERE 5 NOT IN (1, 2, NULL);
```

Пусто! Безопаснее `NOT EXISTS` (следующие уроки) или фильтр `WHERE col IS NOT NULL` внутри подзапроса.

## Запомните

- Подзапрос — `SELECT` в скобках: скалярный (одно значение), список (для `IN`), производная таблица (в `FROM`, нужен псевдоним).
- Коррелированный подзапрос ссылается на внешнюю строку.
- Если внутри `NOT IN` могут быть `NULL` — результат пуст. Следите за этим.
