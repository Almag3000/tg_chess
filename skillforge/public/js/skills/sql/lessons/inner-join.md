## Данные живут в разных таблицах

В хорошо спроектированной базе информация **не дублируется**. Название категории хранится один раз в `categories`, а в `products` лежит только ссылка на неё — `category_id`. Ссылка называется **внешним ключом** (FOREIGN KEY), а столбец, на который она указывает, — **первичным ключом** (PRIMARY KEY).

Схема нашего магазина:

- `products.category_id` → `categories.id`
- `orders.customer_id` → `customers.id`
- `order_items.order_id` → `orders.id`
- `order_items.product_id` → `products.id`

Чтобы показать товар с названием категории, нужно **соединить** таблицы — это `JOIN`.

## INNER JOIN

```sql try
SELECT products.name, categories.name
FROM products
INNER JOIN categories ON products.category_id = categories.id;
```

Читается так: «возьми каждый товар и найди категорию, у которой `id` равен `category_id` товара; склей строки». Условие после `ON` — **условие соединения**.

`INNER JOIN` оставляет только **пары, у которых нашлось соответствие**. Если у товара `category_id` равен `NULL` (у нашей «Подарочной карты» так и есть) — он в результате пропадёт.

## Псевдонимы таблиц

Писать полные названия утомительно, и они не помогают, когда у столбцов одинаковые имена (`name` есть и там, и там!). Дайте таблицам короткие псевдонимы и **всегда** указывайте, из какой таблицы столбец:

```sql try
SELECT p.name AS product, c.name AS category, p.price
FROM products AS p
JOIN categories AS c ON c.id = p.category_id
ORDER BY c.name, p.price DESC;
```

(`INNER` можно не писать — `JOIN` по умолчанию внутренний; `AS` для таблиц тоже необязательно.)

Если столбец с таким именем есть в обеих таблицах и вы не указали префикс, получите ошибку `ambiguous column name`.

## Соединение + фильтры + агрегаты

`JOIN` — часть `FROM`, поэтому всё остальное работает как обычно:

```sql try
SELECT c.name, o.id AS order_id, o.order_date
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE o.status = 'delivered' AND c.city = 'Москва'
ORDER BY o.order_date;
```

## Главная ошибка: забытое или неверное условие

Каждая пара строк, для которой `ON` истинно, попадает в результат. Если условие неверное — получите «чужие» пары. Если условия нет совсем — каждая строка слева соединится с **каждой** строкой справа (**декартово произведение**: 72 заказа × 15 клиентов = 1080 строк). Если результат внезапно разросся — ищите `ON`.

```sql try
SELECT COUNT(*) AS rows_count
FROM orders o
JOIN customers c ON 1 = 1;
```

## Запомните

- Данные разнесены по таблицам, связи — через ключи (`PK` ↔ `FK`).
- `JOIN … ON условие` соединяет строки пары таблиц; `INNER JOIN` оставляет только совпавшие.
- Давайте таблицам псевдонимы и всегда указывайте `псевдоним.столбец`.
- Результат разросся — проверьте условие `ON`.
