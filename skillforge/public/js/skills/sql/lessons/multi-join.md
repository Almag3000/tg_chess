## Цепочка соединений

`JOIN` можно добавлять сколько угодно: каждый следующий присоединяется к тому, что уже собрано. Чтобы узнать, **какие категории товаров приносят выручку**, нужен путь `order_items → products → categories`:

```sql try
SELECT c.name AS category,
       SUM(oi.qty * oi.unit_price) AS revenue
FROM order_items oi
JOIN products   p ON p.id = oi.product_id
JOIN categories c ON c.id = p.category_id
GROUP BY c.name
ORDER BY revenue DESC;
```

Как придумывать такие запросы — «идите по ключам»:

1. Выпишите, **какие данные нужны** (название категории, количество, цена).
2. Найдите таблицы, где они лежат.
3. Проложите путь между ними по внешним ключам.
4. Добавьте фильтры (`WHERE`), группировку, сортировку.

Рисуйте схему на листке — это нормальная практика, а не слабость.

## Самосоединение (self join)

А что, если таблица ссылается **сама на себя**? В `employees` у каждого сотрудника есть `manager_id` — это `id` другого сотрудника из той же таблицы. Чтобы показать имя руководителя, соединяем таблицу с самой собой — под разными псевдонимами:

```sql try
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON m.id = e.manager_id
ORDER BY e.id;
```

Здесь `e` — «сотрудник», `m` — «его руководитель». `LEFT JOIN` нужен, чтобы не потерять директора, у которого руководителя нет (`NULL`).

Так же устроены рекомендации: в `customers.referred_by` лежит `id` пригласившего клиента.

```sql try
SELECT c.name AS customer, r.name AS referrer
FROM customers c
JOIN customers r ON r.id = c.referred_by;
```

## Контроль качества соединения

Перед тем как доверять результату, задайте себе два вопроса:

- **Не размножились ли строки?** Если соединяете «один ко многим» (клиент → заказы), строк станет больше — это нормально, но при подсчёте `SUM` по «одной» стороне итог завысится.
- **Не потерялись ли строки?** `INNER JOIN` молча выбрасывает строки без пары.

Привычка: сравнить `COUNT(*)` до и после соединения.

## Запомните

- Соединения можно цепочкой: идите по внешним ключам от нужных данных к нужным данным.
- Self join — соединение таблицы с собой под двумя псевдонимами (иерархии, рекомендации).
- Следите за размножением и потерей строк.
